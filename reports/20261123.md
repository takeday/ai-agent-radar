## Codex の知見

### [Codexのサンドボックスとネットワークアクセスの違い](https://x.com/ojas_dev/status/2123381203680317455)

Codexはシェルコマンドのインターネットアクセスをブロックできますが、同じエージェントから起動されたMCPサーバーは別のプロセスとして動作するため、ネットワークリクエストを実行できます。これはOpenAIのCodexサンドボックスエンジニアリングのディープダイブで明かされた重要な区別です。

### [Codexサンドボックス内部 | OpenAI](https://openai.com/index/inside-the-codex-sandbox/)

config.tomlで設定されたstdio MCPサーバーについて、Codexハーネスはサーバーの起動に使用するコマンドをサンドボックス化しようとしません。セキュリティ設定時に理解すべき重要なポイントです。

### [Codexのサンドボックス設定ガイド](https://x.com/Rakel076/status/2123345415592456290)

OpenAIが11月18日に公開したCodexサンドボックスについて、macOS、Linux、Windows上でのファイルアクセスとネットワーク制限方法を説明。config.tomlの権限プロファイルでAPIキーなどを含むファイルへのアクセスを「deny」で制限でき、ドメイン単位でのネットワーク制限も可能です。

### [Codex CLI 0.169.0でセキュリティの穴をふさぐ](https://x.com/EmunaEliran/status/2122248054669517264)

Codex CLI 0.169.0から、信頼されていないディレクトリではリポジトリの.codex/config.tomlとMCPサーバーを無視するようになりました。信頼レベルは`codex exec --trust`で明示的に指定するか、~/.codex/config.tomlの`projects.<path>.trust_level`で設定する必要があります。

### [Codexの新しい使い方 — Dominik Kundel & Charlie Guo, OpenAI](https://www.youtube.com/watch?v=IPh9YsWvDQk)

CODE Summit 2026でのプレゼンテーション。Codexが内部ビデオアプリでDaVinci Resolveのフッテージをエディットしてレビュー用にカットを返す、コンテキスト収集からUI高速イテレーション、Codex CLIまで接続エージェントワークフローの実践例を紹介。

### [Codexはどう動作するのか？](https://x.com/call_me_tiwari/status/2123839878920356338)

OpenAIが説明するCodexの3つの重要なコンポーネント：モデル(タスク理解と動作決定)、エージェントハーネス(モデル・ツールループとセッション管理)、実行環境(ローカル、サンドボックス、リモート)。環境によってセキュリティモデルが異なります。

### [Codexのサンドボックス設定で押さえておくべき3つのポイント](https://x.com/kaiponai/status/2123340187711553926)

Codexをローカルで実行する場合、デフォルトの:workspaceでは書き込みは作業フォルダ内のみだが読み込みは.env等を含む広い範囲で可能。config.tomlの権限プロファイルで「`"**/*.env" = "deny"`」のように指定して制限でき、stdioのMCPサーバーはサンドボックス外で起動されるため独立した権限モデルが必要です。
