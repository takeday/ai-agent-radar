## Codex の知見

### [Codex can block a shell command from accessing the internet, while an MCP server launched by the same agent can still make network requests](https://x.com/ojas_dev/status/2123381203680317455)

Codex サンドボックスでは、シェルコマンドはネットワークアクセスがブロックされますが、config.toml で設定されたローカル MCP サーバーは同じエージェント内からでもネットワークリクエストを実行できるという、サンドボックスの仕組みの重要な区別をOpenAIが明かしました。

### [Inside the Codex sandbox | OpenAI](https://openai.com/index/inside-the-codex-sandbox/)

OpenAI による公式ドキュメント。Codex がファイルアクセスやネットワークアクセスをどのように制限するか、config.toml の権限設定ファイルや codex sandbox コマンドでカスタマイズできること、MCP サーバーもサンドボックス内で実行できることを解説しています。

### [Sandbox configuration details for Codex](https://x.com/Rakel076/status/2123345415592456290)

Codex のサンドボックスはデフォルト設定で比較的緩いため、config.toml で default_permissions を設定したり、ファイルパスに read/write/deny を指定したり、ドメイン単位でネットワークアクセスを制限できます。.env や secrets を含むファイルをまとめて禁止することで API キーなどの露出を防げます。

### [Codex CLI 0.169.0 closes a security hole with explicit trust levels](https://x.com/EmunaEliran/status/2122248054669517264)

Codex CLI 0.169.0 では、信頼できないディレクトリで codex exec を実行した際に、リポジトリの .codex/config.toml と MCP サーバーを無視するようになりました。--sandbox workspace-write でも同様で、明示的な信頼が必要になりました。codex exec --trust で有効にするか、~/.codex/config.toml の projects.<path>.trust_level で設定できます。

### [[[Windows][ChatGPT Desktop / Work] Permissions selector disappears after sending first message; Work home forces Cloud/TPP with no Local option and session remains restricted]](https://github.com/openai/codex/issues/62975)

Windows の Codex Desktop アプリで、最初のメッセージ送信後にパーミッションセレクタが消える問題が報告されています。Work モードでは Cloud/TPP が強制され、Local オプションがなく、セッションが制限されたままになる問題です。

### [New Ways of Working with Codex — Dominik Kundel & Charlie Guo, OpenAI](https://www.youtube.com/watch?v=IPh9YsWvDQk)

OpenAI のエンジニアによるデモ。内部ビデオアプリが Codex を使って DaVinci Resolve で映像を編集し、カットを返すワークフローを紹介しています。プラグイン、Appshots、ChatGPT Space を使ったコンテキスト収集から、高速 UI イテレーションまで、連携エージェントワークフローの実践例を示しています。

### [How Codex Works: Model, Agent Harness, and Execution Environment](https://x.com/call_me_tiwari/status/2123839878920356338)

OpenAI は Codex の3つの重要なコンポーネントを説明しています：(1) Model - タスクを理解し何をするかを決定、(2) Agent harness - モデルとツールのループとセッションを管理、(3) Execution environment - コマンド実行とファイルアクセスが行われる環境。この環境はローカルマシン、サンドボックス、またはリモート環境です。
