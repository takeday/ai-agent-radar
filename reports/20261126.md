## Codex の知見

### [Codex can block a shell command from accessing the internet, while an MCP server launched by the same agent can still make network requests.](https://x.com/ojas_dev/status/2123381203680317455)

Codex はシェルコマンドのインターネット接続をブロック可能だが、同じエージェントが起動した MCP サーバーはネットワークリクエストを実行できる。OpenAI が Codex サンドボックスエンジニアリングの深掘り解説で明かしたもの。通常、Codex はファイル書き込みとネットワークアクセスに制限を持つシェルコマンドを実行するが、config.toml で設定したローカル MCP サーバーについては異なる制限モデルが適用される。

### [Inside the Codex sandbox | OpenAI](https://openai.com/index/inside-the-codex-sandbox/)

Codex のサンドボックス機能について OpenAI の公式技術解説。stdio MCP サーバーが config.toml で設定されている場合、Codex ハーネスはサーバー起動用コマンドをサンドボックス化しない。ファイルアクセス、ネットワーク制限、権限設定について macOS・Linux・Windows での動作とカスタマイズ方法を説明している。

### [別以为开了沙箱，Codex 就碰不到你的 API Key……](https://x.com/Rakel076/status/2123345415592456290)

Codex のサンドボックス設定に関する実装ガイド。config.toml でのデフォルト権限設定、カスタム設定の派生方法、ファイルパスの read/write/deny 指定、ドメイン別のネットワーク制限など、実践的な設定方法を紹介している。

### [GPT-6.2 SOL: regression in instruction following, initiative, and task completion compared with GPT-6.1 SOL](https://github.com/openai/codex/issues/62195)

Codex CLI の GPT-6.2 SOL モデルで GPT-6.1 SOL と比べて命令遵循、主動性、タスク完了に関する回帰が報告されている。複数ユーザーから macOS での Computer Use 利用時に GPT-6.1 ではタスク完了するが GPT-6.2 では未完了のまま停止することが確認されている。

### [[Windows][ChatGPT Desktop / Work] Permissions selector disappears after sending first message](https://github.com/openai/codex/issues/62975)

Windows の Codex/ChatGPT デスクトップアプリで最初のメッセージ送信後に permissions selector が消える問題。Mac と Linux でも同様の現象が確認されており、Work モードではクラウド/TPP が強制されてローカルオプションが表示されない。
